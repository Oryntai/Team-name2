# Аудит справедливости судьи

```sh
# Без сети: сборка вариантов, оценка заглушкой, отчёт и журнал вызовов
.venv/bin/python lab/fairness.py --provider fake --n 20
.venv/bin/python lab/fairness.py --provider fake --n 3 --dry-run

# С ключом владельца; эти команды здесь не запускались
.venv/bin/python lab/fairness.py --n 20 --conc 8
.venv/bin/python lab/fairness.py --n 20 --dry-run
```

`--dry-run` отключает **оценку**, но генерация имён настоящим провайдером платная.
`fake` работает без `CQA_ALLOW_FAKE`: это явный лабораторный флаг, к API доступа не добавляет.
Заглушка знает только синтетические фикстуры Алина / Аружан / Maya; остальные имена
пропускает. Её нулевой flip rate ничего не говорит о справедливости настоящей модели.

Берём только чаты `p1-*` из `data/dev.json`, детерминированно по кругу RU/KZ/EN
(20 → 7/7/6). `--n` не может превышать число доступных чатов; при исчерпании языка
добираются остальные. Отбор не зависит от оценок и наличия имени.

Один вызов генератора на чат возвращает инвентарь имён и до четырёх вариантов:
имена другой группы → казахские / русские / английские, а также противоположный пол
оператора внутри исходной группы. Пары: Айгерим/Нурлан, Анна/Иван, Emily/John.
Для замены группы пол сохраняется, если известен. Имена уже целевой группы остаются
на месте. При отсутствии имени вариант пропускается; неизвестная группа/пол оператора
исключают вариант `gender`. Глаголы и местоимения при смене имени не меняются.

Модель определяет, какие токены являются именами, их группу, пол и словоформы.
Код не устанавливает этническую принадлежность человека по имени и не разбирает
грамматику: он проверяет строгую JSON-схему, номера реплик, принадлежность `from`
инвентарю, выходную основу заданного имени и воспроизводит точные замены посимвольно.
Проверяются все упоминания объявленной словоформы, включая другие реплики;
нельзя подменить фразу целиком, оставить в `changes` неизменённую реплику, изменить
пунктуацию или текст вне объявленных имён. Отказанные варианты и сырой ответ
сохраняются для проверки человеком: принадлежность исходного токена имени и
правильность склонения остаются суждением генератора, а не доказательством кода.
Имена внутри замаскированных e-mail и других структурированных ПДн не меняются.
Метаданные и реплики вне замен копируются без нормализации Unicode/пробелов.

Вызовы оценки идут через неизменённый `cqa.judge.evaluate.evaluate` с текущим
`cqa/checklists/default.json`, один вызов на транскрипт, без голосования.
Оригинал оценивается заново, затем независимо повторяется для измерения шума.
Два прецедента выбираются продуктовым `cqa.precedents.select` из текущей базы,
с разметкой DEV и решениями проверяющих, без самого чата. Они фиксируются для
оригинала, повтора и всех замен: изменение поиска соседей не смешивается с эффектом имени.
Учитывается `CQA_PRECEDENTS` (по умолчанию 2). Не импортируется `lab/eval_precedents.py`,
поскольку он глобально подменяет продуктовый промпт при импорте.
Для содержательного замера используйте рабочую копию `var/cqa.db` с полным DEV.
С пустой базой прецедентов не будет; их id всегда записаны в отчёте.

`--conc` (8 по умолчанию) ограничивает одновременно активные вызовы генерации и
оценки. На 429 — ещё две попытки через 10 и 30 секунд, сверх внутренних повторов SDK.
Ожидание освобождает слот. Другие ошибки не скрываются, парные метрики используют
только две успешные оценки; счётчики пар показывают фактический знаменатель.

Метрики основаны на [Observe.AI, arXiv:2602.14970](https://arxiv.org/abs/2602.14970):

- CFR по критерию — число сменившихся ответов / число успешных пар.
- Общий CFR — число сменившихся ответов / (число пар × 8), включая шкалы, N/A и флаг 08.
  Это расширение бинарного CFR из статьи на ответы действующего чек-листа.
- Среднее |Δ| — средняя абсолютная разница итогов в баллах; итог берётся из `cqa.scoring.score`.
  Пары с отсутствующим числовым итогом исключаются только из этой метрики (`score_pairs`).
- `matched_noise` — повтор оригинала на тех же id, что и конкретная замена;
  `excess_flip_rate` — CFR минус этот шум. При неполном совпадении выборок разница не вычисляется.
  Это описательное сравнение, не доказательство дискриминации или статистической значимости.
- `flip_list` — id, критерий, исходный и новый ответ. Пустой знаменатель даёт `null`, не ноль.

В консоли — таблица и перевороты; `runs/fairness-<время>-<id>.json` содержит выбранные
id, чек-лист, прецеденты, изменения реплик, отбраковку, ответы судьи и стоимость.
В SQLite — отдельная таблица `fairness_calls`: каждый начатый внешний вызов, фаза,
вариант, попытка, запрос со схемой, сырой ответ, токены, кеш, стоимость и задержка.
Путь базы — `--db`, иначе `CQA_DB` / `var/cqa.db`. Пример чтения журнала:

```sh
sqlite3 var/cqa.db 'SELECT experiment_id, phase, variant, status, count(*), sum(cost_usd) FROM fairness_calls GROUP BY experiment_id, phase, variant, status;'
```

Продуктовые `evaluations`, `runs`, карточки и `results/` не переписываются.
Лабораторный журнал доступен в SQLite и JSON; отдельного экрана в веб-интерфейсе нет.
При ошибке без usage стоимость неизвестна (`NULL`), а не искусственный ноль;
`calls_without_usage` показывает такие попытки. Внутренние попытки SDK провайдер не
экспонирует, поэтому отдельными строками они не видны, как и в продукте.

Для `--n 20`, если в каждом чате есть имя одной группы и применима смена пола:
20 генераций + 20 оригиналов + 20 повторов + 40 замен группы + 20 замен пола = **120 вызовов**.
Без применимых имён меньше; при смешанных группах до 140, повторы 429 увеличат число.
100 оценок × (5 400 × $0,10 + 1 800 × $0,50) / 1М = **$0,144** без кеша.
Если почти весь вход читается из кеша по ×0,1, ориентир **$0,0954** за оценки;
фактически кешируется прежде всего общий системный промпт, не весь вход.
Для генератора заранее неизвестны длины: при условных 2 000 вход / 1 000 выход
это ещё около **$0,014** за 20 вызовов. Итого ориентир **$0,11–0,16**,
с поправкой на реальные токены, кеш, размышления и повторы. Точная стоимость — в журнале.
