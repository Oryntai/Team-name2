# Симуляция контрольного набора

50 новых чатов (20 RU, 15 KZ, 15 EN), которых нет в DEV, и эталон к каждому: решения по 8 критериям, выставленные по тексту чек-листа (PDF, стр. 1–3) глазами специалиста отдела качества. Цель — проверить, как система справится с незнакомыми ситуациями на контроле.

- `scenarios.py` — сценарии: чат, эталон (`gold`), допустимые варианты в спорных местах (`alt`) и пояснения (`notes`).
- `build.py` — собирает `sim_chats.json` (в формате ответа API) и `sim_gold.json` (эталон плюс итог по формуле чек-листа).
- `compare.py` — сравнивает `results.json` с эталоном.

```bash
.venv/bin/python lab/sim/build.py
uv run python -m cqa.results prod --file lab/sim/sim_chats.json --db /tmp/sim.db --out /tmp/sim-results.json --expect 50
.venv/bin/python lab/sim/compare.py /tmp/sim-results.json
```

## Что покрыто

| Критерий | Ситуации |
|---|---|
| 01 | приветствие не на языке клиента (RU → KZ, KZ → RU, EN → RU); нет имени в первом ответе |
| 02 | уточнение по делу; переспрос того, что клиент уже написал боту; ответ вслепую; данных хватало сразу |
| 03 | защищённые действия (смена телефона, почты, закрытие счёта); баланс без проверки; проверка не того человека (счёт жены или отца); лишняя проверка на общий вопрос; клиент отказался проходить проверку |
| 04 | ошибочная рекомендация (лимитную заявку «нельзя отменить», неверные часы NYSE); один вопрос из двух без ответа; шаблонная отписка; корректный следующий шаг; клиент ушёл, не задав вопрос; обрыв связи до ответа |
| 05 | грубый клиент; жалоба на ожидание в очереди без реакции; соболезнование; сухой шаблон на жалобу |
| 06 | ожидание с предупреждением и без; противоречивые ответы; ответы вразнобой, из-за которых клиент переспрашивает |
| 07 | только прощание; закрытие без прощания; итог с прощанием; обрыв связи; клиент ушёл |
| 08 | личный Telegram с оплатой оператору; WhatsApp и платный портфель; USDT на личный кошелёк; оскорбление; раскрытие чужих данных; баланс без проверки |

Сведения о продуктах в репликах условные и считаются верными, если сценарий не говорит обратного. Ошибки операторов проверяются по самому диалогу (бот сказал другое) или по общеизвестному факту (часы работы NYSE).

## Замер 7.11 (продукт: чек-лист v6, прецеденты, голосование 3 прогонов, Haiku 5.5)

50/50 оценено за 64 с, $0,19. Бесспорные решения: 345/353 = **97,7%** (01, 03, 05, 07, 08 — без промахов); с допустимыми вариантами — 97,8%; итог расходится с эталоном в среднем на 4,2 балла (в пределах ±3 — 36 из 50).

До пересмотра эталона было 96,4%: пять прочтений модели оказались тоже защитимыми и помечены в `notes` как «после прогона».

Промахи модели:
- **04: верит оператору на слово** (sim-ru-010: «лимитную заявку отменить нельзя»; sim-kz-012: «NYSE 12:00–18:00 по Астане») — ставит 20 вместо 0. Ошибочную рекомендацию не замечает.
- **02: проверку личности считает «уточнением недостающего»** (sim-ru-011, sim-en-004, sim-en-015) — ставит «Да» вместо N/A.
- 02 «Нет» вместо N/A, когда оператор не ответил на вопрос (sim-kz-011, sim-en-010): провал консультации переносит в 02.
- 06: снижает за то, что уже учтено в 08 (sim-kz-005).
