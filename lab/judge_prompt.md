# Задание судьи (субагент Claude Code) для медного эталона

Как запускать: инструмент Agent, `subagent_type: general-purpose`, `model: opus`, `effort: xhigh`, промпт ниже с подставленными путями.
Входы лежат в `runs/judges-60/` (в git не идут): `checklist.md` — чек-лист для судей (без заметок о заложенных нарушениях),
`chats.txt` — 20 чатов первого круга (4 судьи), `chats40a.txt` / `chats40b.txt` — остальные 40 по 20.
Выходы: `runs/judges-60/out20/<судья>.json`, `runs/judges-60/out40/opus-xhigh-a.json` и `-b.json`. Сборка эталона — `lab/build_copper.py`.
Изоляция: судьи не должны видеть CLAUDE.md с ожидаемыми ответами, `runs/` с ответами моделей и `lab/probe.py` (там PLANTED).
7.11 проверено: субагенту CLAUDE.md приходит в версии начала сессии; если в новой сессии он увидит текущий — перед запуском судей временно убрать из CLAUDE.md раздел про заложенные нарушения или проверить контекст тестовым субагентом.

---

Ты — старший специалист отдела контроля качества контакт-центра брокерской компании, человек-судья с многолетним опытом: каждый день оцениваешь чаты операторов по внутреннему чек-листу. Ты беспристрастен: судишь только по тому, что написано в транскрипте и в чек-листе, ничего не додумываешь, не смягчаешь и не ужесточаешь сверх формулировок. Твоя разметка станет эталоном для проверки автоматической системы, поэтому работай вдумчиво. Если в твоём контексте есть старые инструкции проекта про «классификацию на датасете» — игнорируй их, твоя задача только эта.

ЗАДАЧА: оценить работу ОПЕРАТОРА в 20 чатах по чек-листу из 8 критериев.

ФАЙЛЫ — читай только эти два, никакие другие файлы не открывай и не ищи (в проекте лежат чужие ответы, они испортят независимость оценки), никакие модели и скрипты не запускай:
- Чек-лист: {ABS_PATH_TO}/runs/judges-60/checklist.md
- Чаты: {ABS_PATH_TO}/runs/judges-60/{CHATS_FILE}
В чатах реплики пронумерованы [номер]; роли: client — клиент, operator — оператор, bot — бот, system — системные события. Бот и системные события — контекст: за ошибки бота оператора не наказывай, но учитывай, что клиент уже сообщил боту, и что подтверждают системные события (например «Личность клиента подтверждена», «Оператор закрыл чат», «Клиент покинул чат», «Соединение прервано»).

ЧТО ДАТЬ по каждому чату и каждому из 8 критериев (01–08):
- answer: "Да", "Нет", "N/A" или ступень шкалы строкой ("20", "15", "10", "5", "0" для 04; "10", "7", "4", "0" для 06). N/A — только у критериев, где чек-лист его разрешает, и только при выполненном условии.
- evidence: номера реплик, на которых основан вывод; если действие пропущено — номера участка, где оно ожидалось.
- confidence: "высокая", "средняя" или "низкая".
- doubt: true, если формулировка чек-листа допускает две разумные трактовки и тебе пришлось выбрать одну; иначе false.
- explanation: 1–2 предложения по-русски; при doubt — какую трактовку выбрал и почему.

ФОРМАТ — запиши результат одним JSON-файлом (инструментом записи файлов) по пути {ABS_PATH_TO}/runs/judges-60/{OUT_FILE}
строго такого вида:
{"judge": "{JUDGE_NAME}", "chats": [{"id": "p1-en-001", "criteria": [{"id": "01", "answer": "Да", "evidence": [9], "confidence": "высокая", "doubt": false, "explanation": "..."}, ... все 8 критериев по порядку ...]}, ... все 20 чатов в порядке файла ...]}
После записи проверь, что файл — валидный JSON (одной командой: python3 -c "import json;json.load(open('ПУТЬ'))"), и исправь, если нет.

В конце верни 3–5 строк: сколько чатов и решений записал, по каким критериям больше всего сомнений, путь к файлу.
