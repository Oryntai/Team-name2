# Защита: сценарий на 5 минут

Порядок — как в ТЗ (стр. 4): интерфейс и диалог → оценка → апелляция → смена критерия. Говорим по-русски.

## Подготовка (до выхода, ~10 минут)

1. Свежая база с актуальным чек-листом: остановить сервер, `rm -f var/cqa.db*`, `uv run python -m cqa` → открыть http://127.0.0.1:8000.
   DEV загрузится сам. Контрольный набор: «Загрузить набор» → новый `group_id` → «Оценить все» (Haiku, ~1 мин на 65 диалогов).
2. Открыть вкладки заранее: список диалогов; карточка `p1-ru-025` (пример N/A); карточка `p1-ru-022` (грубая ошибка);
   звонок `p4-ru-002` (удержание 7 мин); «Чек-лист»; «Журнал».
3. Проверить звук на звонке (плеер), роль в шапке — «Оператор».

## 0:00–1:00 · Интерфейс и диалог

- Список: набор, язык, канал, итог, грубые ошибки; фильтры. «Каждая оценка — живой вызов модели, готовых ответов нет».
- Открыть диалог: транскрипт с исходными метками времени; бот и системные события — контекст, оценивается только оператор.

## 1:00–3:00 · Оценка

- По каждому критерию: ответ, баллы, вес, обоснование. Клик по `[n]` в обосновании → реплика подсвечивается.
- `p1-ru-025`: клиент ушёл, не сформулировав запрос → 04 «N/A» с причиной; вес перераспределён, итог из 100.
- Итог и секции считает код по формуле чек-листа (пример из PDF — 93,08 — в автотестах), модель только отвечает по критериям.
- `p1-ru-022`: грубая ошибка — отдельная плашка, итог не обнуляется.
- Звонок `p4-ru-002`: плеер, переход к секунде реплики; панель «Звонок по меткам времени» — удержание 7 мин 06 с, паузы перед
  ответом, темп оператора (справка, в оценку не входит).
- Журнал: модель Claude Haiku 5.5, ≈ $0,001 и ~9 с на оценку со всеми вызовами.

## 3:00–4:00 · Апелляция

- Роль «Оператор» → у критерия «Оспорить оценку» → комментарий → отправить.
- Роль «Проверяющий» → «Апелляции»: оценка модели, комментарий, фрагмент диалога → «Изменить» + причина →
  баннер «было → стало», в карточке исходная оценка, решение и финальный итог.

## 4:00–5:00 · Смена критерия (жюри называет, какой)

- «Чек-лист» → заменить критерий (название, тип, шкала, вес, N/A) → **«Подсказка ИИ»**: порядок решения и проблемы
  формулировки (пересечения с другими критериями, N/A без условия) → «Вставить в пояснение».
- **«Проверить на 3 диалогах»** — как модель понимает новый критерий, было → стало, без сохранения.
- «Сохранить как новую версию» → план: «вызовов модели N, оценим только новый критерий, перенесём остальное» →
  **«Применить к набору»** → блок «Что изменилось»: поменялся только новый критерий, остальные ответы перенесены
  («Перенесено из оценки №…»). Сменить только вес — пересчёт формулой мгновенно, без вызова модели.

## Если спросят

- **Почему не модель считает итог?** Арифметика по ТЗ детерминирована: веса, N/A, округление — в коде, с автотестами.
- **Приватность.** ИИН, карты, IBAN, телефоны, e-mail, паспорта маскируются до отправки в модель (модель видит «[ИИН скрыт]»).
- **Без облака.** Провайдер «Своя модель · локально» — любой OpenAI-совместимый сервер (vLLM, llama.cpp, Ollama).
- **Встраивание в CRM.** Интерфейс — веб-компоненты; `embed.html?c=<id>` — карточка внутри формы Dynamics 365.
- **Реальная обработка.** Журнал: каждый вызов модели с временем, токенами и ценой; кеша по id диалога нет.

## Запасной план

  показать план и подсказку ИИ (запись экрана заранее).
- Лимит запросов (429): сервер сам повторяет с паузами 5/15/30 с.
