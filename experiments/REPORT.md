# Пробный прогон трёх моделей на DEV

Дата: 7 ноября 2026 года. Все выводы ниже относятся к ограниченному пробному запуску, а не к проверенной точности системы.

## Данные

DEV API вернул 65 записей: 60 чатов и 5 звонков; языки RU 35, KZ 15, EN 15. Транскрипты уже содержат роли `client`, `operator`, `bot`, `system` и временные метки. Для голосового прогона использован один звонок `p4-ru-003` (MP3, 393,2 с), для текстового — чат `p1-ru-001` (12 реплик). У DEV нет разметки правильных баллов чек-листа или эмоций, поэтому по нему нельзя посчитать точность этих двух задач.

Для WavLM использованы 2–3-секундные фрагменты, выделенные по меткам времени транскрипта, затем эмбеддинги сгруппированы `KMeans` в 2 группы. Это проверка прототипного этапа, не измерение стандартной точности диаризации. Метки ролей в транскрипте использованы как ориентир, а не как независимая ручная разметка аудио.

## Решение для хакатона

1. **Приоритет — чек-лист и проверяемые доказательства.** Роли говорящих уже есть в данных. Для 60 чатов голосовой этап вообще неприменим.
2. **Баллы считать кодом, а не LLM.** Модель должна вернуть допустимый ответ и ссылку на реплику; программа проверяет тип ответа, применимость `N/A`, принадлежность доказательства нужной роли и рассчитывает вес. При `N/A` применимые веса нормализуются до 100. Флаг грубых ошибок хранится отдельно.
3. **Эмоцию показывать как вспомогательный сигнал.** В стартовом чек-листе нет самостоятельного штрафа за сарказм; эти метки можно использовать для выбора случая на ручную проверку. Нельзя делать вывод о нарушении только по интонации.
4. **Следующий текстовый эксперимент — более сильная модель.** Проверить на размеченной вручную выборке RU/KZ/EN, что она возвращает корректную структуру, допустимые значения `N/A`, точные реплики и правильные выводы по каждому критерию. 0.5B оставить как отрицательный базовый уровень.
